## 业务背景速览

整条治理链路为:

```
队列(G1–G10,按类目划分,产出带违规码/规则码的 case)
        │
        ▼
自动驳回模型(策略因子 + 正则 + fewshot,召回率 ~95%)
        │  高置信违规 → 直接驳回
        ▼
漏放的 ~5% + 低准确率 case → 进入人审
        │
        ▼
AI 助审 Agent(product_id → 商品信息插件 → 获取规则 → 违规点引用整理)
        │
        ▼
TCS 人审平台(透传疑似违规点,供审核员参考)
```

两个北极星指标:

1. **单 case 人审时长下降**
2. **助审覆盖量扩大**(体裁:静态商品 / 直播 / 短视频;违规类型:假货、虚假宣传、劣质等)

## 核心问题

- 助审信息**精确率仅 ~11%**,召回率 / 准确率约 50%
- 评估数据集本身存在标注偏差(有偏)
- 每个业务场景需重复配置多套自动驳回模型,运营成本高

## 回答要点(TL;DR)

1. **先做分层误差归因,再谈方案**:修正评估集标注偏差(双人标注 + 仲裁,算 Kappa);把「细则定位误差」和「违规点判断误差」分开量化;统计输入信息完整度对精确率的影响;认识到进入人审的是被前置模型筛过的**难样本分布**,精确率低有结构性原因。
2. **高质量数据集 + RAG**:以质检/研判复核结论为 label;存储结构化字段,**固证(evidence)字段最有价值**;检索键用「类目 + 违规码 + 标题 + 主图特征」多路召回而非仅标题 embedding;细则 ID 需版本化以防规则变更导致 label 腐化。
3. **治理检测模型定位为统一的多标签风险分类器**:输出违规码概率 + 置信度,按置信度分层路由(高→直接驳回,中→带预测 Tag 进 Agent,低→直接人审),同时解决多套驳回模型配置成本和 Agent 缺少先验两个问题。
4. **助审产品指标提醒**:低精确率的透传信息可能增加阅读成本并造成锚定效应;应在 TCS 侧埋点做 A/B 对比,给透传信息加置信度标识;覆盖量扩大应跟着精确率走——先在单个「队列 × 体裁」组合做到精确率 60%+ 再横向铺开。
